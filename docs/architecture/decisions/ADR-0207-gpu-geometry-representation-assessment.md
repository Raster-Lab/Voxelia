# ADR-0207 - GPU-produced geometry representability assessment

## Context

`ADR-0197` decision 4(j) makes this the surface-rendering arc's tenth and last
increment, governed by `VOX-SUR-009`: "Geometry generated by Metal compute shall
be representable without making GPU buffers the canonical geometry model."

`ADR-0197` decision 7 bound this increment in two ways. It must not be
pre-judged — whether the answer is a documentation assessment or a built path is
this increment's finding. And its verification methods are **Inspection and
Test**, not the Inspection and Review that licensed `ADR-0196`'s
documentation-only discharge of the GPU-*consumer* question. `VOX-SUR-009`
carries a real test obligation, and a documentation-only discharge would be a
claim this project does not make.

## Findings from inspection

1. **The canonical geometry model is already a pure value.** `TriangleMesh`
   holds a position domain, a topology and attributes, admits on construction,
   and reaches no framework type. `ADR-0196` already added `ModelIO` to
   `VoxeliaGeometry`'s prohibited-import set, and `Metal` was already
   prohibited there. Nothing in the geometry module can name a GPU buffer, so a
   buffer cannot become canonical by accident — only by someone adding a
   dependency edge that the import check would fail.
2. **A governed transfer boundary already exists, and it already ends in owned
   bytes.** `ADR-0186` decision 2 has `MetalBufferTransfer` return a *fresh
   owning* `[UInt8]` copied out of a validated shared-buffer range after the
   writing command buffer has completed. The GPU-to-CPU edge is therefore
   solved, reviewed and scanner-gated already.
3. **What is missing is the layout, not the transport.** Between "owned bytes"
   and "canonical mesh" there is no accepted contract at all. Without one,
   `VOX-SUR-009` is answerable only in the abstract, and the first producer to
   arrive would invent its own layout — which is how a buffer's shape quietly
   becomes the geometry model.
4. **The test obligation is dischargeable without a GPU.** The missing piece is
   a pure function from bytes to a canonical value. It needs no device, no
   command queue and no compute kernel to be exercised exactly, so the **T**
   method is fully dischargeable off-screen. The finding is therefore a **built
   path**, not a documentation assessment.

## Decision

1. **`VOX-SUR-009` is discharged by inspection and by a built, tested layout
   contract.** The four findings above are the inspection; accepted
   `VOXELIA-ALG-0041` defines `gpu-geometry-representation/v1` and the migration
   implements and tests it.
2. **The layout is the contract; the buffer is only transport.** Nothing in
   `ALG-0041` names Metal, a device, a buffer or a command queue. A producer
   conforms by emitting bytes, and the decode is a pure function from bytes to a
   canonical value. This is exactly what keeps a GPU buffer from becoming the
   geometry model: the canonical mesh remains the only authority, and the bytes
   are never consulted again once decoded.
3. **The decoder lives in `VoxeliaGeometry`, and that placement is the
   architectural point.** A byte-layout decoder that mentions no GPU type does
   not require, and must not acquire, a Metal dependency. Putting it in
   `VoxeliaMetal` would have made the geometry path depend on the backend that
   happens to produce the bytes today.
4. **Positions are tightly packed three-component binary32; indices are
   `UInt32`; both little-endian.** MSL's `float3` occupies sixteen bytes with
   four bytes of padding while `packed_float3` occupies twelve. A producer using
   the aligned type must pack before writing. This is the single most likely way
   for a conforming-looking producer to be wrong, so the record states it rather
   than implying it.
5. **Counts arrive out of band and the byte counts must match exactly.** A
   length-bearing header would let the payload decide its own allocation, and
   the caller already knows what it dispatched. Both products are taken against
   the host signed-integer ceiling before use.
6. **The coordinate space is never carried in the payload.** A buffer cannot
   declare a coordinate space, and letting bytes name one would be exactly the
   relabelling `ADR-0183` decision 4 forbids. The caller supplies the
   descriptor, as it does for every other geometry it constructs.
7. **Widening binary32 to binary64 is exact, and no precision is invented.**
   Every finite binary32 is exactly representable in binary64. The honest
   consequence is registered rather than glossed: a producer writing decimal
   `0.1` yields `0.10000000149011612`, and that is the published value.
8. **The decode carries no geometric rule.** Its own failure family is exactly
   four byte-level cases; every geometric rejection — non-finite position,
   out-of-range index — belongs to the canonical value's own admission and is
   not restated. That separation is the architectural claim made operational.
9. **Two canonical cases are structurally unreachable through this path, and
   the record says so rather than carrying a restatement.** `incompleteVertex`
   and `incompleteTriangle` cannot arise, because an exact byte-count match is
   strictly stronger than a multiple-of-three check.
10. **No geometry-producing compute kernel is written, and none is claimed.**
    `VOX-SUR-009` asks whether such geometry is *representable*, not that a
    producer exist. Writing a kernel with no consumer is the expansion
    `ADR-0196` decision 3 refused for the mirror question, and the same
    reasoning holds here. This record states plainly that no accepted
    Metal geometry producer exists; when one arrives it must emit this layout.
11. **No encode direction is defined.** CPU-to-GPU geometry upload is a
    different contract with a different consumer, and inventing it here would
    double the surface for no requirement.
12. **Independent analytical evidence is registered now**: eighteen fixtures,
    eight decoded and ten rejected, with two SHA-256 digests frozen in
    `ALG-0041`.

## Alternatives considered

### Discharge `VOX-SUR-009` by documentation alone, as `ADR-0196` did

Rejected. `VOX-GEO-011` declares `I,R`; `VOX-SUR-009` declares `I,T`. The
verification-method column is the difference, and treating the two rows as
equivalent because their subject matter mirrors would claim evidence that was
never produced.

### Put the decoder in `VoxeliaMetal`

Rejected; see decision 3. The decode names no GPU type, so placing it beside the
backend would make geometry depend on today's producer.

### Read the counts from a header in the payload

Rejected; see decision 5. It lets the payload decide its own allocation, and the
caller already knows what it dispatched.

### Carry the coordinate space in the payload

Rejected; see decision 6. It is relabelling by bytes, which `ADR-0183` forbids.

### Accept MSL's aligned `float3` layout

Rejected; see decision 4. Sixteen-byte-stride positions with padding would make
the layout depend on one shading language's alignment rules, and the padding
bytes would be unspecified content inside a governed payload.

### Write a Metal compute kernel that produces geometry

Rejected; see decision 10. No consumer exists, and the requirement asks for
representability rather than for a producer.

### Also define the CPU-to-GPU encode

Rejected; see decision 11.

## Consequences

`VOX-SUR-009` is discharged: Inspection by the four findings, Test by the
migration's byte-exact reproduction of all eighteen `ALG-0041` fixtures. With it
the `ADR-0197` surface-rendering arc closes.

The deliberate limitations are decode only, positions and indices only,
`UInt32` indices only, and no geometry-producing kernel.

## Affected modules

Documentation and the independent Python oracle only in this increment.
Migration adds the decoder to `VoxeliaGeometry`. **No dependency edge changes,
and specifically no Metal edge is added** — which is the point of the record.

## Compatibility impact

None in this design-only increment.

## Security impact

Allocation is bounded by counts checked against the host ceiling before any
read; errors are payload-free and disclose no bytes, counts or offsets.

## Performance and memory impact

`O(vertexCount + triangleCount)`, with one allocation per decoded array.

## Validation impact

The oracle registers:

```text
fixtureSHA256=055eddda7b501f397741194f7ca2dbc038e0191c87c9e8634f298561d4ae079c
valueSHA256=fc52599c92900bc37cbea6dc206f481a4ee419347628634a67cf5da476ab04c4
fixtures=18 decoded=8 rejected=10
```

Migration must reproduce all eighteen fixtures bit-exactly, prove the
little-endian byte order, prove exact binary32 widening including the extremes
and negative zero, prove that geometric rejections come from the canonical
admission rather than from a restated rule, and prove that the decoded mesh is
independent of the source bytes — mutating or discarding the payload after
decoding must not change the mesh, which is the operational meaning of "the
buffer is not canonical". The prohibited-import check must pass with
`VoxeliaGeometry` still forbidding `Metal`.

## Migration

1. Add the decoder to `VoxeliaGeometry` with every fixture from `ALG-0041`.
2. With that green, `ADR-0197` closes and the M6 colour/overlay arc
   (`VOX-R2D-010/011/015` plus VOI verification) is the next queue item.

## Supersession

This record executes `ADR-0197` decision 4(j) and supersedes no accepted record.
It is the GPU-producer counterpart to `ADR-0196`'s GPU-consumer assessment and
reaches a different outcome for a recorded reason: a different verification
method.
