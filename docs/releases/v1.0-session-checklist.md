# The 1.0 release session — acceptance checklist

Scheduled by `ADR-0413` (2026-08-08). The session is the owner's act:
review each item, accept or amend, then direct the cut. Everything
below is staged.

## 1. Policy and posture (review, accept)

- [ ] **Release policy** — `docs/releases/release-policy.md`
  (`ADR-0408`): versioning, deprecation, diagnostic-change discipline,
  publication contents, dependency security, source-package-only
  commitment.
- [ ] **Known limitations** — `docs/releases/known-limitations.md`:
  the honest list by operation, format and platform.
- [ ] **Platform matrix** — Apple Silicon `arm64`; macOS 15+,
  iOS 18+, tvOS 18+, visionOS 2+.
- [ ] **Batch decisions** — `ADR-0409` through `ADR-0413`: VTK/ITK out
  of scope; CPU-only diagnostic registration; DICOMKit
  fix-what-surfaces; boundary-only AI adapter; this-distribution-only
  validation semantics; no generative output in diagnostic
  presentation; plug-ins revisited post-1.0; photorealistic
  non-diagnostic acceptance; 10% regression threshold.

## 2. Evidence (review, accept)

- [ ] **Test status** — the full suite's literal pass line at the
  release commit (currently 1,461 tests in 285 suites).
- [ ] **Benchmark records** —
  `docs/progress/evidence/benchmark-campaign-2026-08-08.{json,md}`:
  steady-state 169.50 ms / ~6.2 M samples/s window-level on the
  reference hardware; this campaign becomes the regression baseline on
  acceptance.
- [ ] **Validation evidence** — the oracle fixtures
  (`docs/progress/evidence/`), the differential suites, and the
  photorealistic witnesses (accepted `ADR-0412`, re-run green on every
  suite execution).
- [ ] **Dependency inventory** — the SBOM from the release gate;
  approved identities `dicomkit` 2.2.11 and `j2kswift` 11.0.2, exact
  pins.

## 3. The cut (direct, then verify)

- [ ] Bump `VERSION` and `RELEASE.json` to `1.0.0` with the toolchain
  recorded (Apple Swift 6.3.3, macOS 26.5.1, Mac17,4).
- [ ] Run the complete release gate (`prepare-release.sh`) green end
  to end.
- [ ] Update release notes identifying any diagnostic-output-affecting
  changes since v0.2.0 (the M7-M10 record: new operations and models
  are additive; no accepted model changed its numbers).
- [ ] Tag `v1.0.0`, push the tag.
- [ ] Post-1.0 obligations begin: major-version discipline for
  incompatible API changes, deprecation before removal.

## Notes

- The example application (`Examples/VoxeliaCTReference`) is a
  demonstration vehicle, not regulatory evidence, and ships as an
  example only.
- Anything amended in session enters the ledger as an ordinary
  increment before the tag.
