# Voxelia Governance

Voxelia uses a maintainer-led open-source governance model.

## Roles

- **Project Lead:** accountable for mission, scope and release approval.
- **Maintainers:** approve changes and releases.
- **Module Maintainers:** own defined technical areas.
- **Committers:** have repository write access.
- **Reviewers:** provide specialist technical or quality review.
- **Validation Lead:** owns validation evidence and tolerance governance.
- **Benchmark Lead:** owns benchmark methodology and baselines.
- **Security Contacts:** receive and coordinate vulnerability reports.

Initial named appointments are to be recorded after repository creation.

## Decisions

Technical consensus is preferred. Material architecture changes use ADRs and
significant proposals use RFCs. When consensus cannot be reached, the Project
Lead or delegated steering group records the final decision and rationale.

## Protected decisions

The following require independent review:

- project licence or scope changes;
- public canonical data-model changes;
- diagnostic-output-affecting behaviour;
- validation tolerance changes;
- security-sensitive or unsafe code;
- new runtime dependencies;
- release and CI security changes; and
- benchmark baseline replacement.

## Appointments and removal

Maintainers are appointed based on sustained contribution, judgement and review
quality. Access may be removed for inactivity, security reasons, repeated
policy violations or governance decision. Decisions shall be documented while
respecting privacy.
